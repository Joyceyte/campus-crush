## Phase Goal

Pure-infrastructure phase (no UI). The MVP "vertical slice" is the **complete secured per-user data path**; this plan builds the data-store half of it (the profiles table + private photo bucket that Phase 3's onboarding form will write to). Framed as an infrastructure outcome:

> **As** the Campus Crush application, **I want to** persist each student's profile, availability, match preferences, and payment-eligibility state into a dedicated RLS-protected `profiles` row plus a private per-user photo bucket, **so that** onboarding (Phase 3) can save private data — including the conditional Stripe card-save — with no follow-up migration and no cross-user leakage.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated user → Postgres (PostgREST) | Every `profiles` read/write crosses here; RLS is the only thing scoping it to the owner |
| authenticated user → Storage (`storage.objects`) | Every photo read/write crosses here; storage RLS + private bucket are the only thing scoping it |
| profiles row → external identity (Stripe) | The `stripe_*` columns reference an external system; only IDs cross this boundary this phase (no secrets, no charge) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-IDOR-PROFILE | Information Disclosure / Tampering | `public.profiles` cross-user access | mitigate | Owner-only RLS: `(select auth.uid()) = id` on select/insert/update; verified by the two-account test in plan 01-03 (ASVS V4 Access Control) |
| T-01-RLS-INSERT | Elevation of Privilege | Missing INSERT policy causing silent write failure OR an over-broad policy | mitigate | Explicit, separate select/insert/update policies (Pitfall 2); exactly-three-policy grep gate; insert uses `with check`, update uses both `using` + `with check` |
| T-01-BUCKET-PUBLIC | Information Disclosure | Face-photo bucket exposed publicly | mitigate | Bucket created with `public = false`; owner-scoped `storage.objects` RLS on the `{userId}/` prefix; public-URL-unreachable confirmed in plan 01-03 |
| T-01-STORAGE-IDOR | Information Disclosure | Reading another user's photo path | mitigate | `(storage.foldername(name))[1] = (select auth.uid())::text` on every storage policy, guarded by `bucket_id = 'photos'` |
