## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (page heading — "Login here for pilot trials", "Please use your university account") | 36px (`clamp(1.75rem, 4vw, 2.25rem)`), `font-jersey` | 400 | 1.2 |
| Body (helper copy, domain-error explanation, placeholder-page copy) | 16px, Helvetica | 400 | 1.5 |
| Label (Google button text, Sign-out button text) | 15px, Helvetica/Arial | 600 | 1.2 |
| Caption (small print — university list under the button, "signed in as ___" line) | 13px, Helvetica | 400 | 1.5 |

Exactly 4 sizes (36 / 16 / 15 / 13px), 2 weights (400 regular, 600 semibold) — no additional sizes/weights for this phase.

Note: the Google Sign-In button's label uses Helvetica (not `font-jersey`) — Google's brand guidelines require the standard "Continue with Google" button to keep neutral system-sans styling and not be reskinned into a third-party brand's display font. This is the one deliberate exception to "headings use Jersey" in this phase.

## Screen Specifications

### 1. Login screen (`/login`)

Layout mirrors the existing `.hero-bento` / `.hero-panel` split already used on the landing page, oriented to match `specs/MVP design .png`'s login panel (photo | content, not content | photo):

- **Desktop (≥900px):** two-column split, content panel on the right (~42%), full-bleed date photo on the left (~58%). Reuse an existing desaturated date photo asset (e.g. `/park-date.jpeg` or `/blurry-iceskating.jpeg`) treated per `STYLE_GUIDE.md` §5 (`saturate(0.82) brightness(0.9)`, `.grain` overlay, sharp corners, no blur on the foreground image).
- **Mobile (<900px):** single column — full-screen photo-background panel (reuse `.hero-panel`'s mobile treatment: photo background + `linear-gradient(180deg, rgba(247,239,225,0.65) 0%, rgba(247,239,225,0.85) 100%)` scrim), content centered on top, top padding clears the fixed navbar.
- **Content block (both breakpoints), top to bottom:**
  1. Heading: "Login here for pilot trials" — Display style (see Typography), left-aligned on desktop / centered on mobile.
  2. Google Sign-In button (see below) — `md` gap below heading.
  3. Small print beneath the button, Caption style, `var(--ink)` at 60-70% (matching `WaitlistModal`'s `rgba(43,27,18,0.6-0.7)` convention): "Open to UniMelb, Monash, Deakin, RMIT, and La Trobe students." (reuses `EMAIL_ACCEPTED_TEXT` wording from `WaitlistModal.tsx` for consistency).
  4. Decorative accent: a small terracotta location-pin SVG (recolour the mockup's purple pin to `var(--terracotta)` — the project has exactly one accent color; do not introduce purple/indigo). No initial/letter glyph inside the pin (the mockup's "J" is a placeholder, not a requirement).

**Google Sign-In button spec:**
- White (`#FFFFFF`) fill, `1px solid rgba(43,27,18,0.22)` border (matching the existing input border token), fully rounded pill or Google's standard 4px-radius rectangle — use Google's standard rectangular button shape (do not force it into the site's pill convention; this is a third-party brand asset, exempt from `.neon-btn`/`.glass-btn` shaping).
- `min-height: 44px`, `padding: 0.65rem 1.5rem`, `display: inline-flex`, `align-items: center`, `gap: 0.75rem` (icon-to-label).
- Google "G" 4-colour SVG mark, 18–20px square, on the left.
- Label: "Continue with Google" — Label typography (15px / 600 / Helvetica), color `var(--ink)` (not white-on-dark, not terracotta — Google's guidelines call for neutral dark-on-white text).
- Hover: subtle `box-shadow: 0 2px 8px rgba(43,27,18,0.15)`, no color shift (matches Google's own hover spec — do not apply `.neon-btn`'s lift/glow treatment).
- `:focus-visible`: `2px solid var(--terracotta)` outline (this is the one accent touch on the button itself, applied only on keyboard focus, consistent with the global `:focus-visible` rule already in `globals.css`).

### 2. Domain-rejection error state (`/login?error=domain`)

Reuses the same `/login` layout/panel (photo split or mobile photo-background — do not build a separate route/page shell) with the content block swapped for:

1. Heading (Display style): "Please use your university account" (or similar — see Copywriting Contract for exact locked copy).
2. Body copy (Body style, `var(--ink)`): explains which unis are accepted.
3. Error emphasis line (Body style, `var(--terracotta)`): states the account they used isn't eligible.
4. The same Google Sign-In button re-rendered below (so the student can immediately retry with a different Google account) — do not require a separate "Try again" link; the button itself is the retry affordance, per the existing waitlist-modal precedent of showing the same field again after a validation error.

No modal, no dialog — this is a full-page state, reached via query param, not a JS overlay.

### 3. Sign-out control

- A small, understated button/link usable in the header or corner of any authenticated page (`/onboarding`, `/confirmation` placeholders, and later Phase 3/4 pages).
- Style: `.btn-outline` (existing class — transparent bg, `1.5px solid var(--border-dark)`, `min-height: 44px`) at a reduced/compact size, OR a plain text link in Caption style with an underline on hover — planner/executor may pick whichever fits the authenticated-page header it lands in, but must NOT use `.neon-btn` (that's reserved for the primary "join/continue" action elsewhere) and must NOT use terracotta as its fill (sign-out is a neutral, non-primary action).
- No confirmation dialog (see Copywriting Contract — sign-out is not treated as destructive).

### 4. `/onboarding` and `/confirmation` placeholder pages

Out of scope to design in depth (Phases 3 and 4 own the real content). Minimum bar for this phase: parchment background, centered `font-jersey` heading + one line of Body-style copy, using the same page shell/typography tokens as the login screen so the app doesn't visually break between phases. No forms, no photo panels, no additional componentry.
