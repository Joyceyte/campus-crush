<objective>
Ship the first vertical slice of Google sign-in: a real, on-brand `/login` screen that launches the actual Supabase Google OAuth flow, plus the single-source-of-truth partner-domain module that the server-side gate (plan 02-02) and the existing waitlist both consume.

**User story:** **As a** Melbourne uni student, **I want to** open a login screen and press one button to sign in with my university Google account, **so that** I can start using Campus Crush without creating another password.

Purpose: AUTH-01 needs a reachable, branded entry point before any callback logic can be exercised. AUTH-02 needs the domain list to exist in one place before anything can enforce it. Extracting the list first also removes the duplicate-literal drift risk between the waitlist API and the new auth gate.

Output: `/login` renders (default + domain-rejection + oauth-error states), pressing the button redirects the browser to Google's consent screen, `lib/uni-domains.ts` becomes the only place the five suffixes are written down, and every landing-page CTA sends students to `/login` instead of opening the retired waitlist dialog.

**Locked decisions honoured in this plan** (from `02-CONTEXT.md`):
- Google-only auth via Supabase Auth — no email/password, no magic link.
- The five partner domains are the SAME list already used server-side in `app/api/waitlist/route.ts`; reuse/extract it as the single source of truth.
- Login route is `/login`; callback route is `/auth/callback`.
- Visual style matches the existing vintage-romance theme (`--parchment`, `--parchment-deep`, `--ink`, `--terracotta`, `font-jersey`).
- **The waitlist is closed and sign-in replaces it as the landing page's call to action** (user decision, 2026-08-03). Every CTA site points at `/login` and the waitlist dialog is unmounted from `app/page.tsx`. This was previously deferred; it is now a locked requirement of this plan.
- **The waitlist table and `/api/waitlist` are preserved, not deleted** — they are the founding-member source of truth Phase 3 reads to decide free-vs-Stripe. Only the UI entry point is retired. `components/WaitlistModal.tsx` stays on disk, unmounted.
