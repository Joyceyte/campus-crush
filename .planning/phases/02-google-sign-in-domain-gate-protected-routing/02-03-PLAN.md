1. `create or replace function public.is_partner_uni_email(addr text) returns boolean language sql immutable set search_path = '' as $$ ... $$;` — the body lowercases and coalesces `addr` to an empty string, then tests it with `like any (array[...])` against the five wildcard patterns `%@student.unimelb.edu.au`, `%@student.monash.edu`, `%@deakin.edu.au`, `%@student.rmit.edu.au`, `%@students.latrobe.edu.au`. `set search_path = ''` is required to satisfy Supabase's mutable-search-path advisor; because the body touches no tables, the empty search path is safe. ## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-15 | Elevation of privilege | orphaned `auth.users` row for a rejected non-partner sign-in | mitigate | The locked decision rejects at the callback rather than pre-insert, so an `auth.users` row is created before rejection. Three layers stop it acquiring anything: the callback calls `signOut()` immediately, `requireStudent()` re-rejects on every protected render, and the recreated `profiles` INSERT/UPDATE policies require `public.is_partner_uni_email(auth.jwt() ->> 'email')`. The residual — an identity row with zero application data — is accepted, documented in checklist section 7 with a manual purge procedure, and matches the STATE.md note to revisit if abuse is observed. Proved by Task 3 step 20. |
| T-02-16 | Spoofing | Supabase redirect allow-list | mitigate | Exactly four entries are specified, the only wildcard being scoped to the project's own `*-campus-crush.vercel.app` preview namespace. A broader wildcard would let an attacker-controlled origin receive an auth code and mint a session. The checklist states this explicitly and ties the list to `ALLOWED_REDIRECT_HOSTS` in `lib/auth/guard.ts`. Verified by the Task 2 acceptance criterion on the allow-list contents. |
| T-02-17 | Spoofing | Google authorised redirect URI | mitigate | Google's redirect list holds exactly one entry, the Supabase `/auth/v1/callback` endpoint. The checklist calls out that adding the app's own `/auth/callback` here is the common misconfiguration; it would widen the set of endpoints that can receive a Google authorization code. |
| T-02-18 | Information disclosure | OAuth client secret and Supabase keys | mitigate | The secret is entered only in the Supabase dashboard and never enters the repository, the plan text, or the chat transcript.
